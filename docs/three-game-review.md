# Three-game architecture review

This review compares ownership in Last Light Clearing, Skybreak and Clockwork Hollow. The [architecture](architecture.md) remains the reference for common contracts; game-specific source maps live in the [catalog](../CATALOG.md).

| Area | Evidence across the three implementations | Decision |
| --- | --- | --- |
| Application mounting | `application.ts` disposes the previous synchronous session before replacement. `main.ts` guards stale lazy imports and HMR. Each game has a scoped DOM root. | Existing boundary works. Preserve independent entry chunks and synchronous cleanup; no scene manager. |
| Fixed-step timing | Every session uses `browser/clock.ts`; catch-up is bounded and transitions reset it. Platformer jump edges and shooter roll edges are consumed on simulation steps. | Keep the shared clock and local stepping composition. No universal update scheduler. |
| Input capture and action translation | Clearing supplies movement from keyboard/relative drag; Skybreak adds held fire and an evade edge; Hollow needs independent captured touch holds and jump press/release. | Keep action translation local. `src/browser/input.ts` is Clearing's existing input owner, despite its location. Moving it solely for directory symmetry offers little benefit in this pass. |
| Browser focus and interruptions | Page visibility/exit policy already uses `bindPageLifetime`. All three app owners also repeated the same clear-input/defer/check/suspend focusout pattern. | **Refined shared boundary:** `bindSessionFocus` owns the event binding and deferred focus check, guarded by the host abort signal. Each game supplies its focus predicate. This removes three repeated listener/microtask implementations without merging their control rules. |
| Viewport and coordinates | The host measures CSS size and pixel ratio. Clearing has Close/Whole arena projections; Skybreak centers a portrait field; Hollow follows a long horizontal route. Each uses uniform scaling, and relative drags stay in CSS pixels. | Host measurement is appropriate; projections remain local. A generic camera would need genre-specific branches immediately. |
| Cameras | Clearing keeps arena boundaries and offscreen warnings visible. Skybreak has a fixed field. Hollow anticipates horizontal velocity and dead-zones vertical follow. | Keep camera policies in presentation. Hollow's new anticipation and vertical stability require no shared camera abstraction. |
| Collision and geometry | Clearing/Skybreak reuse relative swept-circle contact. Hollow needs axis-separated solid resolution and rectangular hazard/contact eligibility. | Existing shared circle primitive remains useful. Keep Hollow rectangles and platform contact rules local; merging solid resolution into the circle helper would add branches without simplifying its callers. Artwork never supplies physical geometry. |
| Assets and animation | Clearing validates external image atlases and observes actors per simulation step for several renderers. The other games use original Canvas drawing and analytic animation. | Retain cancellable asset preparation and Clearing's typed art contract. Do not force procedural drawing into image bundles or add an asset service. Keep original-art/license provenance in owning docs. |
| Rendering and resources | The host owns one frame loop and lifetime signal; renderers own buffers/GPU resources. Clearing can replace renderers asynchronously. Shooter and platformer Canvas owners dispose synchronously. | Existing host/renderer split works. `WorldPresentation` is Clearing-specific, as its imports show; it should not become a universal renderer interface. Hollow outcome particles now finish on a bounded cosmetic frame clock while its rules remain frozen. |
| AudioBits | All three use `createGameAudio` for lazy activation, voice admission, cancellation, suspension and disposal, with local recipes and adapters. The platformer's additional shell, steam, checkpoint and district cues fit unchanged. | Keep the shared owner. Cue priorities, distance filtering and cooldowns remain local. No audio bus or game-specific replacement lifecycle. |
| UI composition | Each UI displays its own typed state and emits intents. Clearing has upgrade confirmation and appearance changes; Skybreak has combat HUD; Hollow adds checkpoint and district/result menus. | Keep local UI and transition rules. Sharing a screen enum or menu controller would couple unrelated state machines. Shared scoped-style and focus/lifetime practices are sufficient. |
| Typed content | Clearing has weapons/upgrades/rounds, Skybreak has formations/boss tuning, Hollow has authored district geometry, palettes, signs, patrols and vents. | Keep TypeScript content close to rules. No new configuration language, export format, persistence compatibility layer or template generator. |
| Pause/retry/restart/disposal | Every restart replaces a run. Clearing preserves upgrade confirmation boundaries; Skybreak respawns lives within a sortie; Hollow retries at checkpoints while preserving its journey ledger. All sessions explicitly resume from gestures. | Shared interruption bindings are appropriate. Retain the genre-specific distinction between retry, respawn and full restart. Checkpoints do not justify a generic save system. |

## Shared improvement

The implemented shared change removes repeated focusout listeners, queued microtasks and disposed guards from the three app owners. It reuses the existing host abort signal, without another lifetime object or resource registry. No compatibility layer, renderer, dependency, package or public API was added. Existing shared mounting, timing, browser host, circle math, asset preparation and AudioBits ownership remain intact.

Repeated composition of run, clock, input, UI, presentation and sound is still visible in the three `app.ts` files. These are short explicit ownership boundaries with different transition rules, rather than evidence for a universal run/entity framework. A future common helper should address a concrete repeated policy, as the focus binder does.
